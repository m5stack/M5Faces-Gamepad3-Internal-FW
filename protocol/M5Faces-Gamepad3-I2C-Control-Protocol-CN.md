# M5Faces Gamepad3 I²C 控制协议

| 文档信息 | 内容 |
| :--- | :--- |
| 产品名称 | M5Faces Gamepad3 |
| SKU | `A004-V3` |
| 适用固件 | `v03` |
| 接口类型 | I²C |
| 文档语言 | 简体中文 |

---

## 1. 硬件接口

| 项目 | 说明 |
| :--- | :--- |
| 默认 I²C 从机地址（7 位） | `0x08` |
| 可配置地址范围 | `0x08`–`0x77` |
| 通信速率 | Standard Mode `100 kbps` / Fast Mode `400 kbps` |
| IRQ 有效电平 | 低电平有效 |
| 按键消抖时间 | `20 ms` |

### 1.1 IRQ 行为

任意按键状态经过消抖后发生变化（按下或松开）时，模块将 `IRQ` 拉低。主机直接读取 1 字节按键状态后，模块清除本次按键事件并将 `IRQ` 恢复为高电平。

```text
按键状态变化                    主机读取按键状态
     │                                │
─────┘ IRQ 低电平（0）─────────────────┘ IRQ 高电平（1）
```

> 读取配置寄存器不会清除待处理的按键事件。若 `IRQ` 为低电平，主机仍需执行一次按键状态读取。

---

## 2. 通信操作概览

模块支持以下三类 I²C 操作：

| 操作 | 主机访问格式 | 用途 |
| :--- | :--- | :--- |
| 按键状态读取 | 直接读取 1 字节 | 获取当前全部按键状态并清除 IRQ |
| 寄存器读取 | 写入 1 字节寄存器地址，然后读取 | 获取设备 ID、UID、固件版本或当前 I²C 地址 |
| 命令写入 | 写入 `[寄存器地址] [数据]`，共 2 字节 | 触发复位或修改 I²C 地址 |

所有多字节列表均按表中从左到右的顺序传输。

---

## 3. 按键状态读取

当 `IRQ` 为低电平时，主机直接从模块读取固定 1 字节，无需先写寄存器地址。

### 3.1 数据格式

按键位采用低电平有效逻辑：

- `0`：按键已按下
- `1`：按键未按下

| 位 | 掩码 | 按键 |
| :---: | :---: | :--- |
| Bit 0 | `0x01` | 上（UP） |
| Bit 1 | `0x02` | 下（DOWN） |
| Bit 2 | `0x04` | 左（LEFT） |
| Bit 3 | `0x08` | 右（RIGHT） |
| Bit 4 | `0x10` | A |
| Bit 5 | `0x20` | B |
| Bit 6 | `0x40` | SELECT |
| Bit 7 | `0x80` | START |

多个按键可以同时按下。上电且没有按键按下时，按键状态值为 `0xFF`。

### 3.2 示例

| 返回值 | 状态 |
| :---: | :--- |
| `0xFF` | 无按键按下 |
| `0xFE` | UP 按下 |
| `0xEF` | A 按下 |
| `0xEE` | UP 和 A 同时按下 |

判断某个按键是否按下：

```c
bool a_pressed = (key_state & 0x10U) == 0U;
```

---

## 4. 寄存器地址映射

| 寄存器地址 | 可读 | 可写 | 默认值 / 返回值 | 说明 |
| :--- | :---: | :---: | :--- | :--- |
| `0xD0` | 是 | 否 | `0x03` | 设备类型 ID（Gamepad） |
| `0xE0`–`0xEB` | 是 | 否 | 设备相关 | 96-bit MCU UID，共 12 字节 |
| `0xFD` | 否 | 是 | - | 系统复位 / IAP 启动命令 |
| `0xFE` | 是 | 否 | `0x03` | 固件版本号 |
| `0xFF` | 是 | 是 | `0x08` | I²C 地址寄存器 |

> `0xD1`–`0xDF`、`0xEC`–`0xFC` 为未定义地址，请勿访问。

---

## 5. 寄存器读取

### 5.1 读取流程

1. 主机向模块写入 1 字节寄存器地址。
2. 主机发起重复起始条件或新的 I²C 读取事务。
3. 模块从所选地址开始返回该寄存器段的数据。

主机读取的字节数不得超过下表给出的最大长度。

### 5.2 可读寄存器段

#### 设备类型 ID

| 起始地址 | 可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xD0` | 1 | `[0x03]` |

#### MCU UID

| 起始地址 | 最大可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xE0`–`0xEB` | `0xEC - 起始地址` | 从对应偏移开始的 UID 剩余数据 |

UID 在设备上电时读入缓存。完整 UID 从 `0xE0` 开始读取 12 字节，字节顺序与 STM32 UID 存储地址递增顺序一致。

#### 固件版本号和 I²C 地址

| 起始地址 | 可读字节数 | 返回数据 |
| :--- | :---: | :--- |
| `0xFE` | 2 | `[firmware_version, i2c_address]` |
| `0xFF` | 1 | `[i2c_address]` |

固件 `v03` 的 `firmware_version` 返回 `0x03`。`i2c_address` 为当前使用的 7 位从机地址，不包含读写方向位。

## 6. 命令写入

命令写入格式固定为 2 字节：

```text
[寄存器地址] [数据]
```

其他长度的写入不会作为有效命令执行。

### 6.1 系统复位 / IAP 启动（`0xFD`）

| 写入数据 | 行为 |
| :---: | :--- |
| `0x00` | 无操作 |
| `0x01`–`0xFF` | 立即触发 MCU 系统复位，并进入启动加载流程 |

示例：

```text
[0xFD] [0x01]
```

> 本文档仅定义应用固件中的复位入口，不定义后续 IAP 固件传输协议。

### 6.2 修改 I²C 地址（`0xFF`）

| 项目 | 说明 |
| :--- | :--- |
| 有效范围 | `0x08`–`0x77` |
| 生效时间 | 写入后立即生效 |
| 掉电保存 | 是，存储在内部 Flash 中 |

示例：将模块地址修改为 `0x20`：

```text
[0xFF] [0x20]
```

写入完成后，主机必须使用新地址继续通信。建议等待本次写事务完全结束，再访问新地址。写入超出有效范围的值会被忽略。

---

## 7. 主机访问示例

以下伪代码中的地址均为 7 位 I²C 地址。

### 7.1 读取按键状态

```c
uint8_t key_state;
i2c_read(device_address, &key_state, 1);
```

### 7.2 读取固件版本和当前地址

```c
uint8_t reg = 0xFE;
uint8_t info[2];
i2c_write(device_address, &reg, 1);
i2c_read(device_address, info, 2);
```

### 7.3 读取完整 UID

```c
uint8_t reg = 0xE0;
uint8_t uid[12];
i2c_write(device_address, &reg, 1);
i2c_read(device_address, uid, 12);
```

---

## 8. 使用注意事项

- 主机应在检测到 `IRQ` 低电平后读取 1 字节按键状态。
- 按键按下和松开都会产生状态变化事件，主机应处理两种情况。
- 若多个按键同时变化，返回字节表示读取时的完整当前状态，而不是单个按键事件。
- 寄存器读取与按键状态读取使用不同事务流程，请勿混用。
- 修改 I²C 地址后，应保存或重新发现新地址，避免设备在后续启动时失联。
